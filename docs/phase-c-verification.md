## Acceptance-review corrections — 30 October to 1 November 2026

The independent review failed the implementation above with five findings. The original evidence below is preserved as the failed-review record; this section explains each correction and its new evidence. Rulings were recorded in [the plan](phase-c-plan.md#acceptance-review-corrections--30-october-2026) before code changed. No new migration; 0010 untouched; owner semantics unchanged except where a finding required a compatible shared-path tightening, noted per fix.

- **FIX 1, visitor freeze.** Root cause: requirements read only the conversation lead id with no lock or state check, and the visitor handoff path had no resolved guard. Fix: `append(visitor_send)` runs the shared gate under the row lock; `handoff(visitor_freeze)` rejects resolved chats; `crm.save(freeze_conversation_id)` checks resolved/archived status under shared locks taken before the lead write, serializing with owner review/handoff instead of deadlocking. Policy: resolved rejects all visitor writes; pending-owner/requested-handoff rejects sends only; requirements and property context stay allowed there. Tests resolve through the real owner review action and assert zero row changes on rejection, safe post-resolve replay, and lock-held serialization of concurrent owner-resolve/visitor-write pairs.
- **FIX 2, pre-persistence gates.** Root cause: `send()` committed the customer message before `draft()` gated, returning 4xx after persisting. Fix: gates run inside the append transaction, so blocked sends persist nothing and run no inference; `send()` wraps draft failures with an explicit saved-message disclosure preserving the status; the UI refetches the thread on every mutation failure. Crash recovery is unchanged for genuinely authorized appends. Tests cover pending/requested/resolved/stale blocks with exact row counts and zero model calls, sequential and mid-inference state-change disclosure, and the pre-existing crash test.
- **FIX 3, property context.** Root cause: visitor chats stay `property_id=NULL` with no path to set it, so property-scoped FAQs were unreachable. Fix: token-scoped `POST .../context` (versioned, idempotent, freeze-governed like requirements) binding a server-validated active property drawn from the lead's recomputed current matches; `draft()` revalidates retrieval-time versus commit-time `property_id` with an explicit error. BFF allowlist and UI extended minimally (per-match selector, focus indicator). Tests cover lifecycle/replay/stale/resolved, invalid/unauthorized rejection, scoped grounding, cross-property citation refusal, pinned historical citations, and mid-inference context change; the browser journey selects focus and asks a property question.
- **FIX 4, draft claim.** Root cause: concurrent same-key drafts could both pass the replay pre-check, duplicating inference. Fix: a session-level advisory claim per draft key across pre-check, inference and commit (bounded 120 s wait, re-check-then-replay, release in `finally` and on disconnect). One extra session per in-flight draft holds no row locks and no open write transaction during inference; ordering claim → mutate → rows is deadlock-free. Guaranteed: one persisted reply per customer message, no inference on completed replay, no duplicate inference while the claim holds, recovery after claimant failure. Exactly-once external inference is not claimed. Tests use a shared call counter with an external-claim barrier, disconnect release, and flaky-claimant recovery.
- **FIX 5, migration checks.** Executed on the retained database under rollback/read-only: CHECK definitions, owner/visitor acceptance with third-value rejection on both tables, legacy-row validity, visitor FK chains with deferrability, requirements/context activity-failure rollback, and RLS/PUBLIC restrictions. Fresh empty-database application was added in the dedicated-empty-database pattern and remains unexecuted (`TEST_DATABASE_URL` absent); the exact configuration is stated in [Limitations](#limitations).

## Claim-timeout correction — 1 November 2026

The second independent review confirmed the FIX 1–5 corrections (fresh database-free backend 96 passed with the existing warning; fresh focused frontend 35 passed) but found one remaining defect: `conversation.draft()` continued to inference when the bounded claim wait expired without acquiring its advisory claim, and an accelerated in-memory probe reached `model.generate()` with no claim. The contract wording permitting that path is removed; [the plan](phase-c-plan.md#d-draft-claim-serialization) now requires claim ownership before inference. All earlier evidence above is preserved as history; this section records only the correction.

Fix: the `if not held` expiry branch performs a late committed-operation check on a separate connection — replay after fingerprint validation, else a retryable 503 preserving the same request identity — with no inference, no new rows and no unlock of another session's claim. Release on success/failure/disconnect, crash recovery, saved-message disclosure with UI safe retry, and exactly-one persisted reply are unchanged; exactly-once provider execution is not claimed.

New deterministic test `test_claim_timeout_replays_or_rejects_without_inference` uses a test-only 2 s wait (monkeypatched `CLAIM_WAIT_SECONDS`; the production 120 s bound is untouched): an external session holds the claim past the wait; the waiting caller performs zero inference, creates no draft rows or assistant messages, and receives 503 with the truthful saved-message disclosure; the holder's claim is verified intact via `pg_try_advisory_lock`; after release the same key completes with exactly one reply; changed-payload reuse is rejected; a re-held claim replays the completed operation without inference; a changed-payload direct draft is rejected; final counts are one customer plus one assistant message. Fixtures use exact-ID cleanup in `finally`.

Executed evidence, exit code 0, single pre-existing Starlette/AnyIO warning: the new test alone **1 passed in 48.32s**; focused `pytest -q tests/test_chat_database.py tests/test_conversation_database.py tests/test_chat.py tests/test_conversation.py tests/test_integrity_database.py tests/test_faq_database.py --run-integrity-db-tests` **148 passed in 1172.50s (19:32)**. No frontend code changed, so no frontend checks were rerun. One mistyped invocation (a nonexistent `tests/api/test_chat_api.py` path) exited 4 with no tests run and was corrected immediately; it is not test evidence.
