## 1. Executive Summary of Audit 5 Remediations

This focused remediation round directly resolves all five blocker areas identified in Codex's Fifth Independent Release Audit:

1. **Safe by Construction Factual Content**:
   - **Typed Representation (`StructuredCopy`)**: Modeled structured content with `template_id`, `channel`, `presentation_style`, `fact_references` (dict of fact key to expected CRM revision), and `prose_slots` (controlled editorial prose strictly restricted from asserting unverified property facts).
   - **Server-Side Fact Resolution**: Implemented `render_structured_copy(structured_copy, facts)` in `grounding_service.py` to resolve and render authoritative CRM facts server-side. Stale fact references raise `StaleFactReferenceError` (HTTP 409 conflict); missing facts raise `UnsupportedFactClaimError`.
   - **Full Surface Area Coverage**: Applied factual grounding boundaries across headlines, body, CTA, hashtags, and nested campaign plan structures (`validate_campaign_plan()` recursively validates `target_audience_spec`, `staged_launch_payload`, `rationale`, `objective`, and `recommended_placements`).
   - **Audit Claim Regressions**: Added regression tests in `test_growth_grounding.py` verifying that all five audit claims on the 2 BHK ₹1.05 Cr property ("Bedrooms: 5", "Only INR 9,999", "500 sq ft rooftop terrace", "24/7 municipal water", "Private sauna"), compound hashtags (`#Bedrooms5`, `#500SqFtRooftopTerrace`), luxury amenities ("Elevator serves all floors", "Includes a private dock"), and claims hidden in nested campaign plan fields are rejected fail-closed.
   - **Demographic Exemption Distinction**: Excluded demographic buyer income bands (e.g. `INR 25L+ p.a.`) and campaign marketing budgets from property price discrepancy checks to eliminate false positives while preserving strict price validation.

2. **PostgreSQL Freshness & Concurrency Rigor**:
   - **Strict Disposable Database URL Requirement**: `test_growth_database.py` and `backend/scripts/growth_database.py` strictly require `TEST_DATABASE_URL` (refuses to fall back to application database settings or connect to Supabase).
   - **Two-Connection CRM Freshness Race Proof**: Implemented `test_growth_database_crm_freshness_concurrent_two_connections_stale_rejection` with a pre-committed fixture on a setup connection: Conn B commits update to revision 2 first (asserting exactly 1 row changed), and Conn A's subsequent check detects the updated revision, rejects approval with HTTP 409 conflict, and asserts persisted content is untouched.
   - **Reverse Ordering Lock Test**: Implemented reverse ordering test where approval on Conn A holds the property lock first via `SELECT ... FOR UPDATE`, and Conn B's writer waits/blocks until Conn A completes and releases the lock.
   - **Synchronized Two-Connection Channel Regeneration**: Implemented `test_growth_database_synchronized_channel_regeneration_empty_and_approved` using `threading.Barrier(2)` on both empty and existing approved channels, proving serialization without orphaned, duplicate active, or corrupted records.
   - **Production Replacement Rollback Test**: Replaced simulated rollback with `test_growth_database_content_replacement_rollback_preserves_old` invoking the production `store.replace_content_items_for_channels()` method and forcing a real database check constraint violation after supersession, proving transactional rollback restores the prior approved content.

3. **Safe Migrations & Upgrade Path**:
   - **Duplicate Reconciliation Rollout**: Updated migration `0005_growth_engine_channel_concurrency.sql` to include a CTE deduplication query marking older duplicate active rows as `superseded` before creating unique partial index `growth_content_items_single_active_idx`:
     ```sql
     WITH ranked_duplicates AS (
       SELECT id, ROW_NUMBER() OVER (PARTITION BY kit_id, channel ORDER BY revision DESC, created_at DESC) as rn
       FROM growth_content_items
       WHERE status != 'superseded'
     )
     UPDATE growth_content_items
     SET status = 'superseded'
     WHERE id IN (SELECT id FROM ranked_duplicates WHERE rn > 1);
     ```
   - **Single Active Item Test Integrity**: Updated test fixtures in `test_growth_database.py` to use isolated kit IDs per test case, avoiding duplicate active inserts during constraint checks.
   - **Runbook Bootstrap Order**: Updated runbooks to require core schema initialization before Growth Engine migrations, and module invocations with `--run-integrity-db-tests`.

4. **Media Paths & Limits**:
   - **Frontend/BFF Payload Limit Alignment**: Eliminated the 32KB payload limit mismatch in `frontend/src/app/api/growth-engine/[...path]/route.ts` by implementing `parseGrowthBody`. Enforces 15MB limit for voice payloads and 500KB for marketing brief payloads, returning HTTP 413 for oversized payloads before buffering and handling realistic WAV files (>100KB) without truncation.
   - **SAM 3.1 Token Grammar & Official Cookbook Format**: Implemented `parse_sam_token_grammar` in `visual_intelligence_service.py` supporting XML-style token grammar (`<detection><label>...</label><box>[...]</box><confidence>...</confidence></detection>`), line-based detections, and fenced JSON, with strict coordinate bounds, ordering, and non-degeneracy validation.
   - **Muse Image Byte Validation & Persistence**: Implemented `validate_image_magic_bytes` (validating PNG, JPEG, WebP, SVG magic bytes) and converted remote image assets to durable base64 data URIs so creative exports survive upstream URL expiration. Embedded AI concept label watermarks and verified retrieval across restarts.

5. **Release Acceptance Checks**:
   - Gated all live provider interactions behind explicit flags.
   - Verified that CRM 503 outages, upstream provider failures, and invalid state transitions fail closed safely.
   - Preserved all D1/D2 and WhatsApp routes and behaviors with zero regressions.
